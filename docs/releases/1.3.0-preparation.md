# AgentPlat 1.3.0 — release preparation

Status: candidate preparation, not published. The public latest release remains
1.2.0 until registry versions, tags, signatures, exact artifact bytes, provenance
and independent consumers have been verified.

## Scope and compatibility

The coordinated cohort expands from 66 to 68 packages. `@agentplat/runner`
provides a portable browser/Node client; `@agentplat/runner-hub` provides the
opt-in WebSocket dispatcher, PostgreSQL leases, heartbeat recovery and
authenticated REST adapter. Room API accepts an optional runner routes app.
No existing Room/Mesh coordination, approval or action authority is replaced.
Applications provide verified tenant authorization and worker handlers.

Task dispatch is at least once. Lease tokens and session fences protect durable
receipts; they do not cancel external effects or provide effect idempotency.
Tests qualify bounded local behavior, not production-scale operation. Existing
migration SQL, frozen evidence baselines and 1.x compatibility fixtures stay intact.

## Required gates

- Full frozen install, public/production dependency audits, build, type checks,
  unit/adapter checks and existing baseline compatibility gates.
- Real PostgreSQL/WebSocket runner scenarios, including tenant/capability isolation,
  capacity, disconnect/timeout reassignment, heartbeat loss and stale receipts.
- Independent exact tarball consumers with Node (without DOM) and browser types,
  packaged migration SQL and real HTTP/WebSocket completion.
- The protected CI and full release workflow keep all prior checks. Runner tests
  and consumers are additionally required, including consumption of the immutable
  prepared artifact set via `AGENTPLAT_PREPACKED_TARBALL_DIRECTORY`.
- Chrome extension integration is a separately tracked application test. A VM with
  mocked Chrome storage is not proof of a loaded Chrome extension. Record the real
  browser result separately; no business-specific client is included in these packages.

## Dependency remediation

The existing overrides retain grpc 1.14.5, fast-uri 3.1.8 and ip-address 10.7.1.
The candidate additionally pins source-map-js 1.2.2, proxy-addr 2.0.8,
@modelcontextprotocol/client 2.2.0 and @modelcontextprotocol/sdk 1.31.0 to address
new registry advisories. No advisory exception or lifecycle-hook permission is added.
Regenerate the lockfile and require a fresh production audit.

## New npm names and publication

The two runner names were unavailable in the public registry during preparation.
Follow the initial-package registration exception in npm-release-security.md:
review exact bootstrap tarballs and SHA-512, register from a clean maintainer
session using interactive npm authentication/2FA, then configure and verify trusted
publishing for the new names. Use a separate bootstrap version/tag so the release
workflow can publish the unoccupied 1.3.0 candidate with its own provenance. Do
not manually occupy candidate 1.3.0 versions with bytes/provenance that the
protected workflow cannot verify as its exact prepared artifact.

For the enabled direct profile, bind each new publisher to Agentplat/agentplat,
release-direct.yml and npm-release. Preserve the existing owner-only reviewer,
protected-main deployment, OIDC, no write tokens and account 2FA. Publisher flags
alone do not prove the added relationships are valid.

After the PR's required checks pass and source is integrated, run the protected
release dry-run for scope all. The single owner environment approval is allowed
only after exact artifact preparation and cohort review. Registry authentication
that requires the owner's passkey remains the owner's action. Announce publication
only after the post-publication byte/signature/provenance and registry consumer gates.
