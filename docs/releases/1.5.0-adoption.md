# AgentPlat 1.5.0 adoption

Status: coordinated release candidate. The 70-package source cohort is prepared;
publication is not established until the protected OIDC run and registry
verification complete. The previous verified npm distribution is 1.4.0.

## Included source increments

- Native Room threads/replies, bounded message pages and selective context, with
  conversation continuity across Planner calls, workflows and notifications.
- Incremental evidence identities, atomic provider checkpoints, fenced analysis,
  durable results and replayable domain projection.
- Versioned situations, authorized multi-Room change feeds and reviewed learning
  proposals that reuse the existing accepted-memory ledger.
- Shared periodic cost accounts, category sublimits and explicit reconciliation
  connected to all Planner call kinds and other protected model jobs.
- Revision-bound timestamp intents and prepared notice delivery, preserving
  unknown external outcomes and actual adapter receipts.

Detailed guides: [conversations](../planner/conversations.md),
[incremental follow-up](../planner/incremental-followup.md) and
[shared budgets and notices](../planner/shared-budgets-and-notices.md).

## Distribution boundary

Use exact versions of the packages an application actually consumes. Do not use
workspace links, local source or a mixed 1.4/1.5 dependency closure for adoption.
After verified publication, the supported consumer commands include:

```sh
npm install --save-exact @agentplat/framework@1.5.0 @agentplat/rooms@1.5.0 @agentplat/rooms-postgres@1.5.0
```

Optional events/workflows/artifacts adapters must belong to the same coordinated
cohort. Source preparation is not proof that these versions are available.

Release preparation consumes the exact manifest-bound tarballs with
`verify:planner-operations-consumer`. The protected publication verifies archive
identity, sizes, SHA-512 and source before publishing, then checks public bytes,
registry signatures, provenance and clean consumers. The combined public registry
consumer must also pass native conversations, independent migrations, shared
cost admission, workflow receipts and notice recovery using new database pools.

## Explicit schemas and activation

Base Rooms advances from migration 019 to 020. Rehearse on a non-production copy
and stop old adapters before applying it: the previous adapter's migration head
does not include 020. Do not restore an incompatible image or roll migrations
down to force older code to start. Preserve history and roll forward, or follow
an explicitly prepared database restoration procedure.

Workflow migration 001 and artifact migration 002 remain unchanged. Optional
memory, incremental-evidence, room-follow-up and planner-operations each own an
independent ledger; installing the package does not initialize or activate them.
Use `runMemoryRevisionMigrations`, `runIncrementalEvidenceMigrations`,
`runRoomFollowupMigrations` and `runPlannerOperationsMigrations` only in the
intended, authorized schema. Constructors perform no I/O or automatic migrations.

Account/subject access ports, prices, period/calendar policy, workers, provider
credentials, delivery adapters and feature activation remain host responsibilities.
Existing uncertain model calls and deliveries require actual reconciliation,
not resetting identities or balances. Prepared notices do not require model
balance. No new provider connection, paid model job or production activation is
part of package distribution verification.

The checks establish package distribution and bounded software behavior. They do
not establish production-scale evidence, model judgment quality or reliability
of arbitrary providers/transports.
