# Remaining publication work after v0.3

The preceding goal turn made concrete progress: it added retained PostgreSQL
integration evidence and updated the manuscript around observed results.

## Still needed for the strongest empirical contribution

1. Build the four-condition mission harness with a task oracle independent of
   the transition controller. Compare sufficiently capable fixed teams,
   minimally coordinated adaptation, a competent durable workflow baseline and
   governed Morphogenesis. Keep policy, owner authority and total budgets fair.
2. Use a separate pilot to estimate measurement variation and fault exposure;
   freeze the confirmatory workload, seeds, analysis and exclusions before runs.
   Do not retroactively relabel the boundary/integration pilots as confirmation.
3. Measure artifact dependency validity and useful task output, not only retained
   artifact addresses or the number of reorganizations. Report blocked work and
   governance costs alongside safety results.
4. Complete the final publication audit and refresh the PDF/artifact with only
   claims supported by the retained data. Conference formatting, public DOI
   deposit and actual submission are subsequent publication decisions; the
   current goal prepares a reviewable manuscript and reproducible artifacts.

## Integration limits to keep explicit

The v0.3 experiment covers two approved transitions through Team/Work owners,
mandate expiry at use time and application draining. It does not cover independent
hosts, real Mesh admission, an ActionGateway provider, semantic attestations or
global atomicity. Its losing V1 execution remains nonterminal after owner cleanup.
Terminal supersession is an implementation/research issue to specify separately,
not something to hide or silently fix while reporting the original experiment.
