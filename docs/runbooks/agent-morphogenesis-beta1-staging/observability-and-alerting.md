# Observability and alerting

Resolve the declared OTLP, metrics, logs and alert receiver resources before
execution. Telemetry must remain content-free: identifiers, digests, phases,
latencies, counts, resource use and fault events are allowed; prompts, outputs,
private keys and credentials are not. Bind every signal to source commit,
campaign, tenant/mission scope where permitted and failure-domain identity.

Required alerts cover unauthorized activation, duplicate effect, morphology
head fork, lost receipt, witness divergence, KMS denial/revocation, cross-scope
access, Mesh quorum loss, PostgreSQL failover, Temporal worker loss, recovery
SLO breach and supervisor heartbeat loss. Send a synthetic alert before the
campaign and retain the external receiver receipt. During each injected fault,
verify both firing and resolution with bounded timestamps.

Missing telemetry must not silently count as zero. If an alert fails delivery
or a required metric has a gap, pause the campaign, fence new effects and repair
the evidence path. Record query definitions, dashboard/version digests, alert
events, receiver receipts and retention policy. Observability is supporting
evidence, not authority and not production certification.
