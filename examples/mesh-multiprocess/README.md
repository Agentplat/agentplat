# Durable multi-process Mesh example

This example starts two independent Node.js peer processes. Peer A sends one
signed `peer.ping` twice over HTTP. Peer B accepts one durable inbox record and
is then forcibly stopped before processing it. A new Peer B process recovers
the row, commits its snapshot and signed acknowledgement atomically with an
outbox row, and Peer A durably accepts the acknowledgement.

PostgreSQL is scheduling and durability infrastructure only. Signatures,
scope, peer identity and authorization remain protocol/application decisions.
The demo generates ephemeral Ed25519 keys at startup and never writes private
keys to the repository or database.

Run it from the repository root:

```sh
docker compose -f examples/mesh-multiprocess/compose.yaml up -d --wait
pnpm run example:mesh-multiprocess
docker compose -f examples/mesh-multiprocess/compose.yaml down
```

Set `DATABASE_URL`, `PEER_A_PORT` or `PEER_B_PORT` to override the local
defaults. Each run creates a randomly named PostgreSQL schema, validates the
round trip and duplicate behavior, prints a JSON evidence record, and removes
only that schema on exit.

The HTTP bearer token and private keys are generated by the launcher and bound
to the two child processes. The example deliberately does not implement global
peer discovery, hidden retries, exactly-once delivery or database-derived
authority.
